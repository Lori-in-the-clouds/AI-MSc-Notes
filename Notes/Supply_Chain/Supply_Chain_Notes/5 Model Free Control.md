# 1. General Policy Iteration (Model-Free)

Generalized Policy Iteration (GPI) is a framework that alternates between:

- **policy evaluation** (estimating the value function for a given policy)
- **policy improvement** (generating a better policy based on that value function)

<aside>
🚨

**Problem:**

In Model-Free Control, a direct application of this framework is problematic because a greedy policy improvement based on the state-value function $V(s)$ requires a model of the MDP to compute the expected reward and next state value (= we don’t know $\mathcal{R}_S^a$ and $\mathcal{P}_{SS'}^a$):

$$
\pi'(s)=\argmax_{a\in \mathcal{A}}\mathcal{R}_S^a+\mathcal{P}_{SS'}^aV(s')
$$

![image.png](5%20Model%20Free%20Control/image.png)

</aside>

<aside>
✅

**Solution:**

The solution is to use the **Action-Value Function** $Q(s,a)$ instead. Greedy policy improvement over $Q(s,a)$ is **model-free** because the policy is found simply by taking the action with the highest Q-value:

$$
\pi'(s)=\argmax_{a\in \mathcal{A}}Q(s,a)
$$

![image.png](5%20Model%20Free%20Control/image%201.png)

</aside>

# 2. On-Policy vs Off-Policy Learning

A fundamental distinction in model-free control is between how experience is used to update the policy.

- **On-Policy Learning** (”self-learning”) → it learns a policy $\pi$ from experience generated by that **same policy**. *Example:* Sarsa
- **Off-Policy Learning** ("imitation-learning") → it learns a target policy $\pi$ from experience generated by a **different behavior policy** $\mu$. This is useful for learning from human observation or for reusing data from old policies. *Example:* Q-Learning

# 3. $\epsilon$-Greedy Exploration

For an agent to find the optimal policy, it must balance two competing goals:

- **Exploitation** → following the current policy to maximize rewards.
- **Exploration** → trying new actions to find a better policy.

Choosing only greedy actions can lead to getting stuck in a **local optimum**. The $\epsilon$**-greedy policy** is a simple and effective way to ensure continual exploration. With probability $1−ϵ$, the agent chooses the current best (greedy) action, and with probability $\epsilon$, it chooses an action at random:

$$
\displaystyle \pi(a|s) = \begin{cases} \frac{\varepsilon}{m} + 1 - \varepsilon & \text{if } a^* = \underset{a \in \mathcal{A}}{\operatorname{argmax}} Q(s, a) \\ \frac{\varepsilon}{m} & \text{otherwise} \end{cases} \qquad \text{where }\ m = \text{n° of available actions}
$$

<aside>
📌

$\epsilon$**-Greedy Policy Improvement Theorem:**

It states that for any $\epsilon$-greedy policy $\pi$, the new $\epsilon$-greedy policy $\pi'$ with respect to the action-value function $q_\pi$ is **always** an improvement, meaning $v_{\pi′}(s)\ge v_\pi(s)$:

$$
\textcolor{orange}{q_\pi(s,\pi'(s))}=\sum_{a\in \mathcal{A}}\pi'(a|s)q_\pi(s,a)=\frac{\epsilon}{m}\left[\ \sum_{a\in \mathcal{A}}q_\pi(s,a)\right]+(1-\epsilon)\textcolor{green}{\max_{a\in \mathcal{A}}q_\pi(s,a)}\textcolor{orange}{\ge} 

\frac{\epsilon}{m}\left[\ \sum_{a\in \mathcal{A}}q_\pi(s,a)\right]+(1-\epsilon)\textcolor{green}{\sum_{a\in \mathcal{A}}\frac{\pi(a|s)-\frac{\epsilon}{m}}{1-\epsilon}q_\pi(s,a)} = 

 \frac{\epsilon}{m} \left[\sum_{a\in \mathcal{A}}q_\pi(s,a)\right] + \cancel{(1-\epsilon)} \sum_{a\in \mathcal{A}}\frac{\pi(a|s)-\frac{\epsilon}{m}}{\cancel{1-\epsilon}}q_\pi(s,a) =\\

  ‭\cancel{\frac{\epsilon}{m} \sum_{a\in \mathcal{A}}q_\pi(s,a)} + \sum_{a\in \mathcal{A}}\pi(a|s)q_\pi(s,a) - \cancel{\frac{\epsilon}{m}\sum_{a\in \mathcal{A}}q_\pi(s,a)}‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭

=\textcolor{orange}{\sum_{a \in \mathcal{A}}\pi(a|s)q_\pi(s,a)=v_\pi(s)}
$$

Key Mathematical Steps Explained:

- **Why $\ge$ ?**: maximum value is mathematically greater than or equal to any weighted average of the same set.
- **Why the fraction component?**: it represent a **purely greedy policy** extracted directly from the older $\epsilon$-greedy policy $\pi$.
    
    $$
      \pi(a|s) = (1-\epsilon) + \frac{\epsilon}{m} \rightarrow 
    
      \pi(a|s) - \frac{\epsilon}{m} = 1 - \epsilon \rightarrow ‬‭‬‭‬‭‬‭‬‭‬
    
      ‭\frac{\pi(a|s) - \frac{\epsilon}{m}}{1-\epsilon} = 1
    
    ‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭
    $$
    
    **N.B.** This term outputs exactly $1$ for the optimal action $a^*$ (since $\frac{(1-\epsilon + \frac{\epsilon}{m}) - \frac{\epsilon}{m}}{1-\epsilon} = 1$) and exactly $0$ for all sub-optimal actions (since $\frac{\frac{\epsilon}{m} - \frac{\epsilon}{m}}{1-\epsilon} = 0$).
    
</aside>

<aside>
💡

**GLIE Condition:**

For a control algorithm to converge to the optimal policy, the exploration must satisfy the **Greedy in the Limit with Infinite Exploration (GLIE)** condition. It is composed of two main requirements that work together:

- All state-action pairs are explored infinitely many times: $\displaystyle \lim_{k \rightarrow \infty}N_k(s,a)=\infty$
- Policy gradually becomes more "greedy" as it gains experience: $\displaystyle \lim_{k \rightarrow \infty}\pi_k(a|s)=1(a=\argmax_{a'\in\mathcal{A}}Q_k(s,a'))$

The GLIE condition guarantees that the agent first **explores** the environment sufficiently to discover all paths and then **exploits** that knowledge to converge on the best policy it has found.

</aside>

# 4. On-Policy Algorithms

## **4.1. On-Policy Monte-Carlo Control**

It combines Monte Carlo learning with the $\epsilon$-greedy exploration policy. The algorithm works by iterating through episodes:

1. **Sample an episode:** the algorithm samples the $k$-th episode by following the current policy $\pi$. Since it is a Monte Carlo method, it waits until the end of the episode before performing updates.
2. **Update action-values:** for each state-action pair $(S_t, A_t)$ in the sampled episode, the algorithm updates its action-value function $Q(S_t,A_t)$, based on the observed return, $G_t$. The update is incremental and uses a decaying step size to ensure convergence:
    
    $$
    Q(S_t,A_t)←Q(S_t,A_t)+\frac{1}{N(S_t,A_t)}(G_t−Q(S_t,A_t))
    $$
    
3. **Improve the policy:** after updating the Q-values, the policy is improved. The algorithm shifts toward a more greedy policy by using an $\epsilon$-greedy approach where the exploration rate $\epsilon$, decays with each episode. A common decay schedule is $\epsilon=\frac{1}{k}$.

**N.B.** This process guarantees that the algorithm will converge to the optimal action-value function $Q(s,a)→q_∗(s,a)$ under the GLIE conditions.

## 4.2. Sarsa (On-Policy TD Control)

**Sarsa** (State-Action-Reward-State-Action) update its rules based on the sequence of events (S,A,R,S′,A′) that an agent experiences:

$$
Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \Big( R_{t+1} + \gamma Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t) \Big)
$$

Sarsa converges to the optimal action-value function $Q(s,a)→q_∗(s,a)$ under the following conditions:

- The sequence of policies must be **GLIE**
- The sequence of step sizes $\alpha_t$, must satisfy the **Robbins-Monro conditions:**
    - The sum of the step sizes must diverge to infinity → $\sum_{t=1}^\infty \alpha_t=\infty$ (=ensures that the step sizes do not decrease too quickly, allowing information to propagate fully across the entire state space).
    - The sum of the squared step sizes must converge to a finite value → $\sum_{t=1}^\infty \alpha_t^2<\infty$ (=ensures that updates become small over time, allowing the Q-values to stabilize and converge).

## 4.3. n-Step Sarsa

Standard Sarsa updates the Q-value based on a single step (TD(0)). However, we can improve learning by looking $n$ **steps** into the future before bootstrapping. This bridges the gap between TD(0) (1-step) and Monte Carlo ($\infty$-steps). The $n$**-step return** $q_t^{(n)}$ is the sum of the first $n$ rewards plus the estimated value of the state-action pair at step $n$:

$$
q_t^{(n)} = R_{t+1} + \gamma R_{t+2} + \dots + \gamma^{n-1} R_{t+n} + \gamma^n Q(S_{t+n}, A_{t+n})
$$

The update rule simply moves the current Q-value towards this $n$-step target:

$$
Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha (q_t^{(n)} - Q(S_t, A_t))
$$

<aside>
💡

**Bias-Variance Trade-off:**

The choice of $n$ controls the trade-off between **bias** and **variance**:

- **Small $n$ (e.g., $n=1$)** → high bias, low variance. The estimate relies heavily on the current value function $Q$ (**bootstrapping**), making learning more stable and faster, but potentially less accurate.
- **Large $n$ (e.g., $n=\infty$)** → low bias, high variance. The estimate relies mostly on actual rewards, reducing approximation errors but introducing more noise (**Monte Carlo**).
- **Intermediate $n$** → usually provides the best performance by balancing both.
</aside>

## 4.4. Sarsa($\lambda$)

Sarsa($\lambda$) is a more sophisticated algorithm that combines returns from **all possible n-steps** rather than choosing a single fixed $n$. There are two ways to view this algorithm: the theoretical "Forward View" and the practical "Backward View".

### 4.4.1. Forward View Sarsa($\lambda$)

The Forward View defines the target as a **weighted average** of all $n$-step returns. The weight of each $n$-step return decays by a factor of $\lambda$ as $n$ increases. The **$\lambda$-return** $q_t^\lambda$ is defined as:

$$
q_t^\lambda = (1-\lambda) \sum_{n=1}^\infty \lambda^{n-1} q_t^{(n)}
$$

The update rule moves the Q-value towards this combined target:

$$
Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha (q_t^\lambda - Q(S_t, A_t))
$$

<aside>
🚨

**Problem: Non-Causality**

The Forward View is theoretically robust but practically difficult to implement online. To compute $q_t^\lambda$, the agent must know the rewards $R_{t+1}, R_{t+2}, \dots$ for the entire future of the episode. This means the agent cannot update its values until the episode is **completely finished**.

</aside>

### 4.4.2. Backward View Sarsa($\lambda$)

The **Backward View** provides an **online** implementation of the Forward View. It uses an **eligibility trace** $E_t(s,a)$ for each state-action pair. The trace acts as a short-term memory: when a state-action pair is visited, its trace increases, and then gradually decays over time:

$$
E_t(s,a) = \gamma \lambda E_{t-1}(s,a) + \mathbf{1}(S_t=s, A_t=a)
$$

The update happens at every step for **all** state-action pairs, proportional to the TD-error $\delta_t$ and the trace $E_t$:

$$
\delta_t = R_{t+1} + \gamma Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t) \\ Q(s,a) \leftarrow Q(s,a) + \alpha \delta_t E_t(s,a)
$$

# 5. Off-Policy Algorithms

<aside>
💡 **Importance Sampling**

One formal way to perform **off-policy learning** is via **Importance Sampling**. This statistical technique estimates the expected value of one distribution (=Target Distribution $P$) using samples generated from another (=Behavior Distribution $Q$):

$$
\mathbb{E}_{X\sim
P}[f(X)]=\sum P(X)f(X)=\sum{ Q(X)\frac{P(X)}{Q(X)}f(x)}= \mathbb{E}_{X\sim Q}
\left
[ \frac{P(X)}{Q(X)}f(x)\right]
$$

---

Intuitive Interpretation:

We compute the expectation of $f(X)$ (= Value/Reward) with respect to distribution $P$ by using samples drawn from $Q$, but we apply a **Correction Weight**:

$$
\text{Weight}=\frac{P(X)}{Q(X)}
$$

- $P(X)\gg Q(X)$ → rare ($Q$ low) but important events ($P$ high) get a large weight, so they strongly influence learning.
- $P(X) \ll Q(X)$ → a frequent ($Q$ high) but unimportant events ($P\approx0$) get almost zero weight, so they are ignored.
- $P(X)\approx Q(X)$ → the weight is about $1$, so the sample is kept unchanged.
</aside>

## 5.1. Off-Policy Monte-Carlo Learning

In Monte Carlo methods, we first collect an episode and compute the return $G_t$ by following the **behavior policy  $\mu$**. We then use this experience to update the value function of the **target policy** $\pi$. Since the episode was generated by a different policy, **Importance Sampling** is used to correct the return before performing the update. This correction is computed as a product of the ratios of the policies probabilities for each action in the episode:

$$
G_t^{\pi/\mu} = \frac{\pi(A_t|S_t)}{\mu(A_t|S_t)} \cdot\frac{\pi(A_{t+1}|S_{t+1})}{\mu(A_{t+1}|S_{t+1})} \cdots \frac{\pi(A_T|S_T)}{\mu(A_T|S_T)} G_t
$$

The value function is then updated towards this corrected return:

$$
V(S_t)\leftarrow V(S_t)+\alpha(G_t^{\pi/\mu}-V(S_t))
$$

## 5.2. Off-Policy TD

This approach also uses a TD target from the behavior policy $\mu$ to evaluate the target policy $\pi$. However, it only requires a single importance sampling correction at each step, resulting in a much lower variance than the Monte Carlo approach. The update rule is:

$$
V(S_t) \leftarrow V(S_t) + \alpha \left[ \frac{\pi(A_t|S_t)}{\mu(A_t|S_t)} \left(R_{t+1} + \gamma V(S_{t+1})\right) - V(S_t) \right]
$$

## 5.3. Q-Learning

**Q-Learning** is a crucial off-policy method that learns the action-value function $Q(s,a)$ **without using importance sampling**. The core mechanism involves two distinct policies:

- **Behavior Policy ($\mu$)** → used by the agent to **choose and execute the action $A$** in the environment. This policy drives exploration.
- **Target Policy ($\pi$)** → this is the policy the agent is trying to learn. It is purely **greedy** with respect to the current $Q(s,a)$ function.

The algorithm acts according to $\mu$ but updates its Q-function as if it had chosen the best action defined by $\pi$:

$$
Q(S_t, \textcolor{purple}{A_t}) \leftarrow Q(S_t, \textcolor{purple}{A_t}) + \alpha \left[\underbrace{ \textcolor{purple}{R_{t+1}} + \gamma \textcolor{green}{\max_{a}} Q(\textcolor{purple}{S_{t+1}}, \textcolor{green}{a})}_{Q-Learning\ Target} - \underbrace{Q(S_t, \textcolor{purple}{A_t})}_{Current\ Estimate\ (\mu)} \right]
$$

<aside>
📌

**Why Q-Learning Bypasses Importance Sampling**

Importance Sampling is usually required in **off-policy learning** to correct the mismatch between the **behavior policy** and the **target policy**. Q-learning avoids this problem by not computing an weighted average over the behavior policy, instead, it directly uses the **max operator.**

</aside>
