# 1. ViT (=Vision Transformer)

Vision Transformers adapt the Transformer architecture for images, replacing convolutions with **self-attention**.

1. Images are divided into **fixed-size patches** (e.g., $16×16$ pixels).
2. Each patch is flattened, linearly projected into a vector, and combined with **positional embeddings** to preserve spatial information.
3. A special `[CLS]` token is prepended to the sequence and serves as a **global image representation** used for classification.
4. The sequence is fed into a **Transformer encoder**, allowing global attention across patches, overcoming CNNs’ local receptive field limits.
5. The `[CLS]` token’s final embedding is sent to an MLP head to produce class scores for prediction.

**N.B.** The dimension of the input patches is a hyperparameter: **Smaller patches** → **longer output** → **better results** (but memory limitations, so we can’t divide each pixel in a batch).

## 1.1. ViT vs CNN

| **Feature** | **CNN** | **ViT** |
| --- | --- | --- |
| **Core Operation** | Convolution: local filters extract features | Self-attention: models relationships between all patches |
| **Input Representation** | Pixels as a 2D grid | Patch tokens (flattened patches as a sequence) |
| **Receptive Field** | Local (global via deep stacking) | Global from the first layer |
| **Inductive Bias** | Strong (locality, translation invariance) | Weak (learns spatial structure from data) |
| **Data Requirements** | Lower (works well on smaller datasets) | Mostly constant (same tokens & dimensions) |
| **Architecture** | Hierarchical (↓ resolution, ↑ channels) | Mostly constant (same tokens & dimensions) |

<aside>
📌

**ViT vs. ResNet (CNN) in Performance**

- **Inductive Bias & Data** → CNNs (e.g., ResNet) have strong spatial biases, making them data-efficient and effective on small datasets like ImageNet-1k. ViTs lack these inductive biases and must learn all spatial relationships from scratch, requiring large-scale pre-training (e.g., ImageNet-21k, JFT-300M) to match or surpass CNN performance.
    
    ![image.png](3%20Vision%20Transformers/image%201.png)
    
- **Computational Efficiency** → ViTs use global self-attention with large matrix multiplications, which parallelizes well on GPUs/TPUs and achieves higher accuracy per FLOP. CNNs rely on local convolutions and pooling, limiting global context early on.
</aside>

## 1.2. Improving ViT

ViTs are highly data-hungry due to weak inductive biases, so enhancing their performance and data efficiency relies on:

- **Regularization and Data Augmentation** → to prevent overfitting and improve generalization, ViTs use:
    - **Weight Decay** → penalizes large weights to reduce overfitting
    - **Stochastic Depth** → randomly skips layers during training
    - **Dropout** → applied in feed-forward layers
    - **MixUp & RandAugment** → generate augmented images for training
    - **CutMix** → combines portions of different images to create new sample

- **Knowledge Distillation (DeiT)** → a training technique where a smaller and more efficient **student  ViT** learns to mimic the behavior of a larger **teacher model** (e.g., a CNN or large ViT), enabling high accuracy with fewer parameters and less data.
    1. The teacher model learns from ground-truth labels using **cross-entropy loss**.
    2. The student tries to match the teacher’s **predicted probability distributions** using **KL Divergence Loss**.
    
    <aside>
    📌
    
    **Architectural Implementation: The Distillation Token**
    
    In models like **DeiT**, a **Distillation Token** is added alongside the standard **`[CLS]` token** to improve knowledge transfer from a teacher model. The two tokens learn from different signals:
    
    - the **`[CLS]` token** is trained with **ground-truth labels**
    - the **Distillation Token** is trained to match the **teacher’s predictions**
    
    Through self-attention, both tokens interact with each other and with the image patches, allowing the model to combine information from the data and the teacher, improving accuracy and data efficiency.

# 2. Hierarchical ViTs: Swin Transformer

This architecture introduces 3 novelties to introduce **spatial inductive biases**:

- **Hierarchical structure**  **(→ Scale Invariance):** unlike standard ViTs, which are **isotropic** and maintain the same resolution across all layers, the **Swin Transformer** progressively reduces the spatial resolution, creating a hierarchical representation.
    
    <aside>
    💡
    
    **Scale invariance:** the ability to detect and segment objects regardless of their size or distance in the image.
    
    </aside>
    
- **Window-based attention + shifted windows (→ Locality):** restricts attention to local regions while allowing information exchange between neighboring windows.
    
    <aside>
    💡
    
    **Locality:** architectural assumption that pixels or tokens that are close to one another in space are highly correlated and share meaningful information.
    
    </aside>
    
- **Relative positional biases instead of absolute positional embeddings** **(→ shift invariance)**
    
    <aside>
    💡
    
    **Shift Invariance:** the ability of a model to recognize the same object or feature regardless of its position in the image.
    
    </aside>
    

## 2.1. Focus on: Hierarchical Structure

The model is organized into different stages:

1. The input image $H \times W \times 3$ is first split into **non-overlapping $4 \times 4$ patches**. This produces a feature map of size: 

$\frac{H}{4} \times \frac{W}{4} \times C$.
2. At the beginning of each subsequent stage, a **Patch Merging** operation builds the hierarchical structure:
    1. **Reduces spatial resolution** by merging each group of $2 \times 2$ neighboring patches (downsampling by a factor of $2$).
    2. **Increases feature dimensionality** by concatenating their representations (from C to 4C).
    3. To control computational cost, a linear layer is then applied to **reduce the channels from $4C$ to $2C$.**
    
    **N.B.** These operations, progressively: **reducing spatial resolution**, **increasing channel depth.**

<aside>
🚨

**Attention Complexity Comparison:**

- **Standard ViT (Global Self-Attention) [$O(N^2)$]** → every patch attends to all other patches in the image. With $N$ patches, this results in $O(N^2)$ computations.
- **Swin Transformer (Window-Based Attention) [$O(M^2N)$]** → attention is restricted to **local windows** of size $M\times M$ (e.g., 7×7 patches). Each window contains $M^2$ tokens, so we have $(M^2)^2 = M^4$ interactions per individual window. Since the total number of windows in the image is $\frac{H}{M} \times \frac{W}{M} = \frac{N}{M^2}$, the total computational complexity is:
    
    $$
    
    M^4 \cdot \left(\frac{N}{M^2}\right) = M^2N
    $$
    
</aside>

## 2.2. Focus on: Shifted Window Attention

In standard **window-based attention**, self-attention is computed only within **non-overlapping local windows**. This makes the computation efficient but limits interaction between different regions of the image. To overcome this, the Swin Transformer introduces **Shifted Window Attention**. Across successive Transformer blocks, the model alternates between:

- **regular window partitioning**
- **shifted window partitioning**

By shifting the windows, patches that were previously in different windows can now interact. This enables **cross-window connections**, gradually restoring **global information flow** while keeping the computation efficient.

![image.png](3%20Vision%20Transformers/image%203.png)

## 2.3. Focus on: Relative Position Bias

**ViT** uses **absolute positional embeddings**, added to input tokens to encode their position. **Swin Transformer**, instead, uses a **relative positional bias** inside the attention:

$$

A = \text{Softmax}\left(\frac{QK^T}{\sqrt{D}} + B\right)V
$$

where $B$ encodes the **relative position between patches**.

## 2.4. **Performance (Speed vs Accuracy)**

The Swin Transformer balances **speed and accuracy** efficiently, achieving top performance on ImageNet and surpassing architectures like **RegNetY, EfficientNet, and ViT with distillation (DeiT)**.

# 3. MLP-Mixer

Unlike Vision Transformers, which rely on self-attention to combine information across patches, **MLP-Mixer** uses only **MLPs** to mix information, showing that attention mechanisms are not strictly necessary.

## 3.1. Architecture

Each MLP-Mixer block contains two stages:

1. **Channel-Mixing MLP** → allows communication **within a single patch** by taking all the features of one specific patch and mixing them, it operates on channel depth ($C→C$). This is how the model understands local details.
2. **Token-Mixing MLP** → allows communication **across different patches** by taking the same channel from all patches and mixing them, it operates on the sequence length ($N→N$). This is how the model understands the global structure of the image.

<aside>
📌

**Key Features:**

- **Skip connections** preserve gradients and prevent signal degradation in deep networks.
- **CNN-like behavior:** token mixing is similar to a depthwise convolution (=applies a spatial filter to each channel independently); channel mixing is analogous to a 1×1 convolution.
- **Data requirements:** performs well only when pre-trained on extremely large datasets (e.g., JFT), otherwise ViTs often outperform it.
</aside>

# 4. DETR (=**DEtection TRansformer)**

Detection Transformers (DETR) aim to use **transformers for object detection**, replacing traditional components like anchor boxes and NMS. Transformers naturally produce a **sequence**, whereas object detection requires a **set of objects**. DETR resolves this mismatch using **object queries**.

## **4.1. How it works?**

1. The input image is processed by a **CNN backbone** to extract a feature map, which is flattened and combined with **positional encodings** to create the input embeddings.
2. These features are passed through a **Transformer encoder.**
3. The **Transformer decoder** receives the encoder output through cross-attention, together with a fixed set of learned vectors called **object queries** (typically ~100). It processes them in parallel (non-autoregressively) and refines them to represent potential objects. 
4. Each query is passed through a **feed-forward network (FFN)** to output:
    - a **bounding box**
    - a **class label** (or “no object”)

![image.png](3%20Vision%20Transformers/image%204.png)

<aside>
📌

**Focus on Object Queries**

The problem with transformers is that you get an output of the same length of the input, so if my image is divided into 9 patches I will always get as output 9 bounding boxes. To avoid this problem we feed to the decoder a list of vectors called object queries, while the embeddings of the patches are fed via cross attention. In this way the number of patches and final outputs are completely independent.

</aside>

## 4.2. Training & Loss

The model predicts a fixed number $N$ of objects (e.g., 100), while an image contains only a few real objects. An optimal **one-to-one matching** is found using the **Hungarian algorithm.** Once the matching is established, the loss combines:

- **Classification Loss (cross-entropy):** matched predictions learn the correct class, while unmatched ones predict the **“no object”** class. Since most queries do not match any object, the loss for this class is **down-weighted** (e.g., $×0.1$) to prevent the model from focusing too much on the background.
- **Bounding Box Loss:** a combination of **L1 loss** (coordinate differences) and **GIoU loss** (measuring overlap between predicted and ground-truth boxes).

**N.B**. During inference, the number of predictions is fixed by the set of **object queries**, which naturally limits the maximum number of detectable objects.
