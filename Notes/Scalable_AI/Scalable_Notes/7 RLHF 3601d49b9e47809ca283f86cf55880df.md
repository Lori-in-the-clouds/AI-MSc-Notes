# 1. Motivation and Initial Challenges (Pre-RLHF)

LLMs are initially trained with self-supervised next-token prediction on large web datasets. While this allows them to learn language patterns effectively, base models are not naturally able to follow user instructions and may generate hallucinations, incorrect information, or toxic content due to noisy training data. To address these limitations, the main goals became: 

- **Instruction following**
- **Truthfulness**
- **Non-toxicity**

## 1.1. First Approaches (Without RLHF)

Before reinforcement learning, instruction following was mainly improved through supervised fine-tuning and prompting techniques:

- **FLAN (Finetuned Language Models Are Zero-shot Learners)** → a pre-trained model is fine-tuned on many tasks described with natural language instructions. This helps the model generalize to unseen tasks and improves zero-shot performance, especially for models larger than ~8B parameters.
    
    ![image.png](7%20RLHF/image.png)
    
- **T0 (Multitask Prompted Training)** → the model is trained directly on curated multitask datasets containing instructions and task examples. This helps it generalize to new tasks, but it has less general knowledge because it is not pre-trained on large web data.
    
    ![image.png](7%20RLHF/image%201.png)
    
- **LIMA (Less Is More for Alignment)** → shows that instruction following can improve using only a small number of carefully selected prompts (around 1,000). It highlights the importance of high-quality data over large quantities.

**N.B.** These methods improved instruction following and model alignment, but they did not completely solve the problem.

# 2. RLHF (Reinforcement Learning from Human Feedback)

Introduced with models like InstructGPT, RLHF is the standard method for aligning LLMs with human intentions and preferences. The pipeline consists of three fundamental steps:

1. **Supervised Fine-Tuning (SFT)** → the base model is trained on high-quality human-written instruction–response examples, where annotators provide both the prompt and the ideal answer. This gives to the model basic instruction-following and dialogue ability.
2. **Reward Model (RM)** → the SFT model generates multiple answers for the same prompt. Humans rank them from best to worst. A separate reward model is then trained to predict these preferences as a single score. It’s built from the SFT model by replacing the final vocabulary layer with a linear layer that outputs a single reward score.
3. **Reinforcement Learning (PPO)** → the model generates outputs that are scored by the reward model. Using Proximal Policy Optimization, the model is updated to prefer high-reward responses while keeping changes limited to avoid damaging prior knowledge.

**Challenges:**

- **Complex pipeline:** SFT → RM → RL makes training complicated
- **Instability:** reinforcement learning can be hard to stabilize
- **High cost:** training the reward model and running RL requires significant compute resources. In addition, during the RL phase, the policy model, reference model, and reward model often need to be loaded into GPU memory simultaneously, increasing memory and hardware requirements.
</aside>

## 2.1. **Training Objectives**

### 2.1.1. Reward Model Loss

The goal is to minimize the following loss function:

$$
loss(\theta) = -\frac{1}{\binom{K}{2}} E_{(x, y_w, y_l) \sim D} [\log(\sigma(r_{\theta}(x, y_w) - r_{\theta}(x, y_l)))]
$$

Where:

- $\binom{K}{2}$: binomial coefficient representing the number of possible pairs from $K$ responses.
- $\mathbb{E}_{(x, y_w, y_l) \sim D}$: expectation over the dataset $D$, where $x$ is the prompt, $y_w$ is the winner response, and $y_l$ is the loser response.
- $r_{\theta}(x, y)$: scalar reward predicted by the model with parameters $\theta$ for a prompt–response pair.
- $\sigma$:sigmoid function that converts the difference between rewards into a probability.
- $-\log(\cdot)$: negative log-likelihood loss, minimized to increase the probability that the preferred response receives a higher score than the rejected one.

### 2.1.2. PPO Loss

PPO is a reinforcement learning algorithm that controls how much the model is updated at each step. It uses a clipping mechanism to prevent large changes, keeping the model stable and close to its original behavior:

$$
L^{CLIP}(\theta) = \hat{\mathbb{E}}_t \left[\min\left(r_t(\theta)\hat{A}_t, \text{clip}(r_t(\theta), 1 - \epsilon, 1 + \epsilon)\hat{A}_t\right)\right]
$$

Where:

- $\hat{\mathbb{E}}_t$: average over time steps $t$.
- $r_t(\theta)$: ratio between the new and old policy probabilities $\frac{\pi_{\theta}}{\pi_{\theta_{old}}}$.
- $\hat{A}_t$: estimated advantage at time $t$ (=how much better a specific action was compared to what the model usually expects to achieve in that situation).
- $\text{clip}(\dots)$: function that limits $r_t(\theta)$ to the range $[1-\epsilon, 1+\epsilon]$.

### 2.1.3. RL Objective Function (What to maximize in PPO)

The optimization process aims to maximize a composite objective function that balances three distinct components:

$$
   ‭objective(\phi) = E_{x \sim D,y \sim {\pi_{\phi}^{RL}}} \left[r_{\theta}(x, y) - \beta \log\left(\frac{\pi_{\phi}^{RL}(y|x)}{\pi^{SFT}(y|x)}\right)\right] + \gamma E_{x \sim D_{pretrain}} \left[\log(\pi_{\phi}^{RL}(x))\right]‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬ ‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭
$$

- **Reward Maximization (**‭

$r_{\theta}$‬**)** → encourages the model to generate outputs $y$ for a given prompt $x$ that receive high scores from the reward model.
- **KL penalty ($\beta$)** → keeps the RL policy close to the original SFT model, preventing large deviations, reward hacking and loss of language quality.
- **Pre-training term ($\gamma$)** → preserves general language ability and world knowledge by maintaining performance on the original pre-training distribution.

**N.B.** $objective(\phi)$ computes the expected reward of a complete response generated by the current model $\phi$. This value is used to compute the **Advantage** $\hat{A}_t$ for each token, which is then used in the PPO loss to update the model.

# 3. Alternatives to Traditional RLHF

## 3.1. DPO (Direct Preference Optimization)

DPO is an alternative to RLHF that avoids the high computational cost and instability of reinforcement learning. Instead of training a separate reward model and using PPO, DPO directly optimizes the language model using human preference pairs.

<aside>
🔢

**DPO Loss (Optional):**

The goal of DPO is to optimize the policy directly using preference data, bypassing the need for an explicit Reward Model:

1. We start with the standard RLHF objective, where the goal is to find a policy $\pi_\theta$‬ that maximizes the human reward $r(x, y)$‬‭‬‭‬‭‬ ‭‬‭‬while minimizing the KL divergence from a reference model $\pi_{ref}‬$:
    
    $$
    \max_{\pi_\phi} \mathbb{E}_{x \sim \mathbb{D}, y \sim \pi_\phi(y|x)} \underbrace{[r_\theta(x, y)]}_{\text{Reward Model}} - \beta D_{KL} [\underbrace{\pi_\phi(y|x)}_{\text{Policy to be optimized}}\parallel \underbrace{\pi_{ref}(y|x)}_{\text{Reference Policy}}] 
    
    $$
    
2. The optimal policy for a given reward function $r(x,y)$ has a mathematically exact solution:‬ 
    
    $$
    \pi_r(y|x) = \frac{1}{Z(x)} \pi_{ref}(y|x) \exp \left( \frac{1}{\beta}\cdot r(x, y) \right)
    $$
    
    Where $Z(x)$‬‭‬‭‬‭‬ is the partition function, a normalization term that depends only on the input $x$:
    
    $$
    Z(x)=\sum_y \pi_{ref}(y|x)\exp\left[\frac{1}{\beta}\cdot r(x,y)\right]
    $$
    
    By rearranging the $\pi_r(y|x)$ equation, we can express the reward function $‭r(x,y)$‬‭‬‭‬‭‬‭‬‭‬ in terms of the optimal policy and the reference model:
    
    $$
    
    r(x,y)=\beta \log \frac{\pi_r(y|x)}{\pi_{ref}(y|x)}+\beta \log Z(x)
    $$
    
    This proves that maximizing the reward is equivalent to increasing the probability of an output relative to the reference model.
    
3. Human preference data consists of triples $(x, y_w, y_l)$, where $y_w$  is the preferred response and $y_l$ the rejected one. Preferences are modeled using the Bradley–Terry formulation:
    
    $$
    
    P(y_w \succ y_l|x)=\sigma(r(x,y_w)-r(x,y_l))
    $$
    
4. Substituting the reward expression into the preference model gives:
    
    $$
    
    P(y_w \succ y_l|x)=\sigma\left(\beta \log \frac{\pi_{\phi}(y_w|x)}{\pi_{ref}(y_w|x)}
    -\beta \log \frac{\pi_{\phi}(y_l|x)}{\pi_{ref}(y_l|x)}
    
    \right)
    $$
    
    **N.B.** The "cancellation" of $Z(x)$ is what makes DPO efficient: we no longer need to compute the sum of all possible outputs.
    
5. The model is trained by minimizing the negative log-likelihood of the human preferences:
    
    $$
    L_{DPO}(\pi_\phi; \pi_{ref}) = -\mathbb{E}_{(x, y_w, y_l) \sim \mathbb{D}} \left[ \log \sigma \left( \beta \log \frac{\pi_\phi(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log \frac{\pi_\phi(y_l|x)}{\pi_{ref}(y_l|x)} \right) \right]
    $$
    
</aside>

## 3.2. Zephyr (Alignment via Distillation)

Zephyr is an alignment method for smaller open-source LLMs that replaces human feedback with AI-generated feedback, reducing the cost of alignment. It’s composed of three phases:

1. **dSFT (Distilled Supervised Fine-Tuning)** →  a powerful teacher model (e.g., GPT-4) generates high-quality responses for a dataset of prompts. These prompt–response pairs are then used to fine-tune the smaller model.
2. **AI Feedback (AIF)** → multiple responses generated by different models are evaluated and ranked by a strong LLM, such as GPT-4, replacing human annotators. This step is important because DPO requires pairs of **preferred** $y_w$ and **rejected** $y_l$ responses. Therefore, AIF generates the preference data needed for the next stage.
3. **dDPO (Distilled Direct Preference Optimization)** → the smaller model is optimized with DPO using the synthetic preference rankings produced in the previous step:
    
    $$
    L_{DPO}(\pi_\phi; \pi_{ref}) = -\mathbb{E}_{(x, y_w, y_l) \sim \mathbb{D}} \left[ \log \sigma \left( \beta \log \frac{\pi_\phi(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log \frac{\pi_\phi(y_l|x)}{\pi_{ref}(y_l|x)} \right) \right]
    $$
    

**N.B.** This technique is especially useful when training open-source models with limited data and computational resources compared to companies like OpenAI.

## 3.3. GRPO (Group Relative Policy Optimization)

GRPO improves pairwise preference learning by evaluating multiple responses generated for the same prompt as a **group**. The algorithm proceeds as follows:

1. For a given prompt, the current policy generates several different responses.
2. Score each completion with a reward model.
3. Each score is normalized using the **mean and variance of the whole group.** This converts raw scores into relative **Advantages** $A_i$:
    - Outputs **above** the group average get a *positive* advantage (rewarded).
    - Outputs **below** the group average get a *negative* advantage (penalised).
    
    **N.B.** This removes the need for a separate **value model**, saving a significant amount of memory.
    
4. Compute a surrogate loss using clipped probability ratios between the current policy and old policy, with a KL penalty for stability.

# 4. DeepSeek-R1 (2025)

DeepSeek-R1 follows a multi-stage training strategy where **RL is used to discover reasoning skills**, while **SFT is used to improve reliability, readability, and language consistency.**

## 4.1. DeepSeek-R1-Zero (The Pure RL Experiment)

The base model (**DeepSeek-V3 Base**) is trained directly using **GRPO** with only **rule-based verifiable rewards** (e.g., checking correct math/code answers and enforcing `<think>` tags via regex). This setup shows that reasoning abilities can emerge **purely from reinforcement learning signals**, without any human-written reasoning data.

**Limitations:** it often produces poorly readable outputs and **language mixing** (e.g., switching between English and Chinese within the same response).

## **4.2. The Final 4-Stage Pipeline**

1. **Cold-Start SFT** → the base model is fine-tuned on a small, high-quality dataset of human-curated long Chain-of-Thought (CoT) data. This teaches the model to stay focused, produce readable reasoning paths, and structure outputs as `<think> reasoning </think> answer`.
2. **Reasoning RL (DeepSeek-R1-Dev-1)** → large-scale reinforcement learning (GRPO) is applied, focusing mainly on math, logic, and coding tasks.
3. **Rejection Sampling + Multi-domain SFT (DeepSeek-R1-Dev-2)** → high-quality outputs from Dev-1 are selected and mixed with general human data (writing, safety, translation). A new model (**DeepSeek-V3 Base**) is then fine-tuned on this combined dataset using SFT.
4. **Final RL (DeepSeek-R1)** → a final RL stage aligns the model with human preferences for helpfulness and safety, producing the final optimized model.
