# 1. Introduction

<aside>
💡

**Scaling laws** are empirical relationships that allow the performance of large models to be estimated without fully training them to convergence. This reduces compute, time, and cost. They also make modern black-box models more predictable and easier to interpret.

</aside>

# 2. Scaling Laws for Neural Language Models (Kaplan et al., 2020)

The primary goal of this research was to establish the relationship between compute $C$, dataset size $D$, number of parameter $N$, and the final performance of the model, measured by the test loss. The study identified eight main scaling laws:

1. **Scale matters more than architecture** → performance depends strongly on scale $(N, D, C)$ and only weakly on architectural shape. 
    
    <aside>
    📌
    
    **Model Shape vs Scale:**
    
    As we can see in the graph below, changes in model architecture like:
    
    - $d_{model}$: dimension of residual stream
    - $d_{ff}$: dimension of intermediate feed forward layer
    - $n_{layer}$: number of layers
    - $n_{heads}$: number of attention heads per layer
    
    have a much weaker effect on final performance compared to changes in scale:
    
    ![image.png](8%20Scaling%20Laws/image.png)
    
    </aside>
    
2. **Predictable scaling and bottlenecks** → model performance improves in a predictable way as model size ($N$), dataset size ($D$), and compute ($C$) increase, as long as none of them is limiting the others. As shown in the graph:
    
    
    - If $N$ grows without enough $D$, performance stops improving because it does not have enough data to learn from.
    - The dashed curves eventually flatten, showing that once the model becomes too large for the available dataset, adding more parameters no longer improves performance.
    
    ![image.png](8%20Scaling%20Laws/image%201.png)
    
    <aside>
    📌
    
    **Magic ratio for efficiency**
    
    Efficiency depends on $N^{0.74}/D$. If model size increases $8\times$, dataset size only needs to increase about $5\times$ to stay optimal. As shown in the graph, moving to the right corresponds to having more parameters per data point. In this region, the model becomes oversized relative to the available data and starts to overfit:
    
    ![image.png](8%20Scaling%20Laws/image%202.png)
    
    </aside>
    
3. **Power-law behavior** → ****performance exhibits a power-law relationship with the three scale factors: 
    
    $$
    y=(cx)^a
    $$
    
    Where:
    
    - $y$ → test loss
    - $x$‬ → the resource being scaled (e.g., compute, data, or parameters)
    - $c$, $a$‬ → constants that depend on the task
    
    In log scale, the equation becomes linear:  $\ln(y) = a \ln(x) + a \ln(c)‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭‬‭$. This linear form makes it possible to extrapolate performance: by training smaller models, we can observe the trend in log space and predict how larger models will behave.
    
    ![image.png](8%20Scaling%20Laws/image%203.png)
    
4. **Predictable training curves** → training curves are predictable, so we can estimate the final loss by looking at the early part of training and extrapolating it, even across different model sizes.
    
    ![image.png](8%20Scaling%20Laws/image%204.png)
    
5. **OOD predictability** → ****we can predict how well the model will perform on OOD (=out-of-domain) data by looking at the training validation accuracy. There is a strong and predictable correlation between the two: as the loss decreases on training/validation data, it also decreases proportionally on external unseen data, usually with a constant offset.
    
    ![image.png](8%20Scaling%20Laws/6ad24973-5b2f-4517-b926-fc3ad70c0841.png)
    
6. **Sample efficiency** → large models are more sample efficient than small ones. They reach a specific target loss in fewer optimization steps and using less tokens than smaller models.
    
    ![image.png](8%20Scaling%20Laws/0470d3df-d203-41a8-88d0-ecee3ff68afc.png)
    
7. **Inefficient full convergence** → convergence is Inefficient. It is better to train larger models for fewer steps than smaller models to full convergence under a fixed compute budget.
    
    ![image.png](8%20Scaling%20Laws/ca32bfc7-ed87-4ffc-948c-945cbe1220bc.png)
    
8. **Critical batch size** → the ideal batch size ($B_{crit}$) mainly depends on the target loss rather than model size, and is determined empirically. Experiments show that the critical batch size approximately doubles for every $13\%$ reduction in loss.
    
    ![image.png](8%20Scaling%20Laws/image%205.png)

# 3. Scaling for Transfer Learning (Kaplan et al., 2021)

This study extends scaling laws to **transfer learning**, a technique where a model reuses knowledge learned from a previous task instead of training from scratch to solve a new task:

1. **Effective Data Transferred $D_T$**→ represents the equivalent amount of target-domain data that the model has already learned via pre-training:
    
    $$
    D_T = k (D_F)^\alpha (N)^\beta
    $$
    
    Where:
    
    - $k$ **(transfer Coefficient):** constant that represents the similarity between the pre-training and target datasets.
    - $\alpha$ **(fine-tuning Data Exponent):** determines how the benefit of pre-training scales with the amount of fine-tuning data.
    - $\beta$ **(Model Size Exponent):** controls how transfer benefits scale with model size $N$.
    - $D_F$**:** fine-tuning dataset size.
    - $N$: model size.
    
    As shown in the graph, pre-training is especially beneficial when the fine-tuning dataset $D_F$ is small:
    
    ![image.png](8%20Scaling%20Laws/image%206.png)
    
2. **Data Distribution Similarity** → the similarity between the pre-training dataset and the target task determines the efficiency of transfer learning. This similarity is captured by the power-law parameters, especially $k$. For example, pre-training on mixed text-and-code data transfers much better to Python tasks than pre-training on text-only data:
    
    ![image.png](8%20Scaling%20Laws/d7617c7c-9efd-4f11-bdd6-16d7e039470e.png)
    
3. **Ossification** → in some cases, pre-training can hurt performance compared to training from scratch. This mainly happens for small models trained on large fine-tuning datasets. For large models, pre-training remains beneficial in most cases.
    
    ![image.png](8%20Scaling%20Laws/image%207.png)

# 4. Emergent Abilities (Wei et al., 2022; Schaeffer et al., 2023)

LLMs were initially believed to exhibit **emergent abilities**, meaning some capabilities (e.g., reasoning or arithmetic) appeared suddenly only after the model reached a certain scale. However, later studies showed that this apparent discontinuity is often caused by the evaluation metric itself.

- **Discrete metrics** such as Exact Match or Multiple-Choice Accuracy give zero credit to partially correct answers, creating the illusion of sudden jumps in performance.
    
    ![image.png](8%20Scaling%20Laws/1d8fadc5-c049-46bd-ba45-f0c19b7ea54e.png)
    
- **Continuous metrics** such as edit distance or Brier score reveal that these abilities actually improve gradually and predictably as model scale increases.
    
    ![image.png](8%20Scaling%20Laws/image%208.png)

# 5. Complicating Scaling Laws

Standard scaling laws assume a continuous improvement in performance, but real-world scenarios introduce complexities, specifically regarding task difficulty and training protocols.

## 5.1. U-Shaped and Inverse Scaling (Wei et al., 2022)

On some reasoning tasks, increasing model size can first *reduce* performance, a phenomenon called **inverse scaling**.

- **Cause:** training data often contains human reasoning mistakes. Medium-sized models are strong enough to learn these patterns, so they also learn the errors, which lowers accuracy.
- **U-shaped recovery:** with further scaling, very large models overcome these distractors and recover performance, producing a **U-shaped curve**.
- **Mitigation:** prompting techniques such as **1-shot prompting** or **Chain-of-Thought (CoT)** can help mitigate this issue and stabilize performance.

![image.png](8%20Scaling%20Laws/9da99562-d12b-45b8-bee2-ffbbb84d109e.png)

## 5.2. Transcending Scaling Laws (Tay et al., 2022)

Scaling laws are strictly bound to the specific training configuration used. Modifying the training protocol (cross-entropy) can shift the entire scaling curve.

### 5.2.1. New Train Procedure: UL2

The procedure does not replace standard pre-training but extends it with a negligible additional cost ($\sim 0.1\%$ compute):

1. **Base Model** → start from a standard pre-trained model (e.g., PaLM).
2. **Continual Training** → continue training for a short additional phase (~0.1% compute) on the same dataset, but with a hybrid objective combining:
    - *Prefix Language Modeling*: predict the continuation of a text sequence (e.g. “The quick brown fox `<targets>`”).
    - *Long-Short Span Corruption*: reconstruct missing parts of the input (e.g. “The `<targets>` fox jumped over the lazy dog”).

<aside>
📌

**Mixture of Denoisers (MoD)**

The core idea is to combine different denoising strategies so the model learns complementary abilities:

- **Regular Denoising** → small portions of the text (avg. span length of 3 tokens) are masked or replaced with sentinel tokens at a corruption rate of roughly 15%.
    
    Goal: learn local context and grammar.
    
- **Extreme Denoising** → the noise level is significantly increased, by corrupting up to 50% of the original text or by replacing very long sequences (avg. span length of 32 tokens).
    
    Goal: forces the model to understand **global context** and long-range dependencies.
    
- **Sequential Denoising** → text is corrupted from the beginning to a random point.
    
    Goal: train coherent continuation and narrative generation, similar to prefix language modeling.
    
</aside>
